# Internationalization (i18n) Design

**Date:** 2026-03-21
**Status:** Approved

---

## Goal

Extract all user-visible text from the DocVault frontend into language files, allowing translators to add new languages by dropping a JSON file and one line in a manifest. Zero Python changes required for new languages.

## Architecture

Vanilla JS i18n — no library dependency. Four components:

1. **Language files** — flat JSON files, one per language, served as static assets
2. **Manifest** — `i18n/manifest.json` lists available locales; drives the language picker
3. **Loader** — async fetch in `lcars.js` on page init, `t()` helper exposed globally
4. **Application** — `data-i18n` attributes on HTML elements; `t()` calls in JS for dynamic content

Language selection: browser `navigator.language` default, overridden by `ui:language` in `settings.db`. Override UI is a compact `<select>` in the sensor rail populated from the manifest. Page reloads on change to apply translations cleanly.

---

## File Structure

```
frontend/static/i18n/
  manifest.json    ← lists available locales + display names
  en.json          ← source of truth (~226 keys, estimate)
  es.json          ← Spanish
  fr.json          ← French
```

Served as static files alongside `lcars.css`. **Adding a new language** = add `{code}.json` + one line in `manifest.json`. No Python changes required.

---

## Manifest

```json
[
  { "code": "en", "label": "EN" },
  { "code": "es", "label": "ES" },
  { "code": "fr", "label": "FR" }
]
```

`lcI18nLoad()` fetches this first to populate the language picker. If the manifest fetch fails, the picker falls back to a hardcoded `["en"]` list.

---

## Key Naming Convention

Flat dot-namespaced keys. No nested JSON objects — flat keys are simpler to iterate and easier for translators.

```
nav.*              Navigation pill labels
sensor.*           Sensor rail labels
common.*           Shared UI text (Save, Cancel, Loading, Error…)
vault.*            Vault page
vault.label.*      Vault page form labels
vault.status.*     Vault task status strings
search.*           Search page
settings.*         Settings page
settings.group.*   Settings accordion group names
utils.*            Utilities page
identity.*         Identity page
optimizer.*        Optimizer page
lab.*              Lab page
telemetry.*        Telemetry page
```

Interpolated strings use `{variable}` placeholders:
```json
"vault.showing": "Showing {from}–{to} of {total}"
```

Missing keys fall back to the key string itself — visible and debuggable, never silent.

## Loader (`lcars.js`)

### Module-level state

```javascript
let _i18n    = {};   // populated by lcI18nLoad()
let _locales = [];   // populated by lcI18nLoad() from manifest
let _activeLang = 'en';
```

### `t(key, vars = {})` — global helper

```javascript
function t(key, vars = {}) {
  let s = _i18n[key] ?? key;   // missing key returns key itself — visible, debuggable
  for (const [k, v] of Object.entries(vars))
    s = s.replaceAll(`{${k}}`, v);
  return s;
}
```

### `lcI18nLoad()` — fetch manifest + translation file

```javascript
async function lcI18nLoad() {
  // 1. Fetch manifest (drives picker; non-fatal if missing)
  try {
    const r = await fetch('/static/i18n/manifest.json');
    if (r.ok) _locales = await r.json();
  } catch (_) {}
  if (!_locales.length) _locales = [{ code: 'en', label: 'EN' }];

  // 2. Determine language: settings.db → navigator.language → 'en'
  let lang = '';
  try {
    const r = await fetch('/api/settings');
    if (r.ok) {
      const data = await r.json();
      const entry = (data.settings || []).find(s => s.key === 'ui:language');
      if (entry) lang = entry.value || '';
    }
  } catch (_) {}
  if (!lang) lang = (navigator.language || 'en').split('-')[0];
  // Only accept a lang that exists in the manifest
  if (!_locales.find(l => l.code === lang)) lang = 'en';
  _activeLang = lang;

  // 3. Fetch translation file; fall back to 'en' if fetch fails
  for (const candidate of lang === 'en' ? ['en'] : [lang, 'en']) {
    try {
      const r = await fetch(`/static/i18n/${candidate}.json`);
      if (r.ok) { _i18n = await r.json(); return; }
    } catch (_) {}
  }
}
```

### `lcApplyI18n()` — DOM scanner

Applies translations to three attribute types. Uses `childNodes` iteration for `data-i18n` to avoid destroying child elements (e.g. icons inside buttons):

```javascript
function lcApplyI18n() {
  // Replace text-only content — ONLY safe on leaf text nodes.
  // For elements with child nodes (icons, badges), wrap the text in a <span data-i18n>.
  document.querySelectorAll('[data-i18n]').forEach(el => {
    // If element has only a single text node child (leaf), replace safely.
    // If it has element children, only the first text node is replaced.
    const firstText = [...el.childNodes].find(n => n.nodeType === Node.TEXT_NODE);
    if (firstText) {
      firstText.textContent = t(el.dataset.i18n);
    } else {
      el.textContent = t(el.dataset.i18n);
    }
  });
  document.querySelectorAll('[data-i18n-placeholder]').forEach(el => {
    el.placeholder = t(el.dataset.i18nPlaceholder);
  });
  document.querySelectorAll('[data-i18n-title]').forEach(el => {
    el.title = t(el.dataset.i18nTitle);
  });
}
```

**Constraint:** `data-i18n` must only be placed on elements where the translatable text is either the sole content or wrapped in a dedicated `<span>`. Never place `data-i18n` on a composite element (e.g. a button containing both an SVG icon and text) — wrap the text part in a `<span data-i18n="...">` instead:

```html
<!-- Composite element — wrap text, not the parent -->
<button class="lc-btn">
  <svg>…</svg>
  <span data-i18n="vault.rebuild_index">Rebuild Index</span>
</button>
```

### Updated `lcInit()`

`lcInit` becomes `async`. The `DOMContentLoaded` listener calls it without `await` — this is intentional; the browser event loop is not blocked. **Constraint:** no page-level JS may call `t()` synchronously at `DOMContentLoaded` time. All `t()` usage must be inside functions called by `lcInit()` or triggered by user interaction after init completes.

```javascript
async function lcInit() {
  await lcI18nLoad();     // resolves language + caches translations
  const navEl = document.querySelector('.lc-nav');
  if (navEl) {
    navEl.innerHTML = buildNavHTML();   // uses t() — translated before insertion
    const page = document.body.dataset.page || '';
    const activeKey = UTILITIES_SUBPAGES.includes(page) ? 'utilities' : page;
    const pill = navEl.querySelector(`[data-nav="${activeKey}"]`);
    if (pill) pill.classList.add('active');
    lcBuildLangPicker(navEl);          // inject language selector into sensor rail
  }
  lcApplyI18n();
  lcPollSensors();
  setInterval(lcPollSensors, 5000);
  if (!document.getElementById('lc-toast')) {
    const t = document.createElement('div');
    t.id = 'lc-toast';
    t.className = 'lc-toast';
    document.body.appendChild(t);
  }
}

document.addEventListener('DOMContentLoaded', () => lcInit());
```

### `lcBuildLangPicker()` — language selector

Appended to the sensor rail after nav injection:

```javascript
function lcBuildLangPicker(navEl) {
  const rail = navEl.querySelector('#lc-sensor-rail');
  if (!rail) return;
  const wrap = document.createElement('span');
  wrap.className = 'lc-sensor lc-lang-picker';
  wrap.id = 'lc-s-lang';
  const sel = document.createElement('select');
  sel.id = 'lc-lang-select';
  sel.setAttribute('aria-label', 'Language');
  _locales.forEach(loc => {
    const opt = document.createElement('option');
    opt.value = loc.code;
    opt.textContent = loc.label;
    if (loc.code === _activeLang) opt.selected = true;
    sel.appendChild(opt);
  });
  sel.addEventListener('change', async () => {
    try {
      await fetch('/api/settings', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ key: 'ui:language', value: sel.value }),
      });
    } catch (_) { /* best-effort; reload anyway */ }
    location.reload();
  });
  wrap.appendChild(sel);
  rail.appendChild(wrap);
}
```

## HTML Markup

Three `data-i18n-*` attributes cover all static text cases:

| Attribute | Target property | Use case |
|---|---|---|
| `data-i18n="key"` | First text node | leaf text nodes only (see constraint above) |
| `data-i18n-placeholder="key"` | `element.placeholder` | `<input>`, `<textarea>` |
| `data-i18n-title="key"` | `element.title` | tooltip / title attributes |

**Before:**
```html
<button class="lc-btn">Rebuild Index</button>
<label>Scan Directory</label>
<input placeholder="Search document content…">
```

**After:**
```html
<button class="lc-btn" data-i18n="vault.rebuild_index">Rebuild Index</button>
<label data-i18n="vault.label.scan_dir">Scan Directory</label>
<input placeholder="Search document content…"
       data-i18n-placeholder="search.placeholder_content">
```

Existing text content is preserved as English fallback — the page is readable before JS runs.

## Dynamic JS Text

Template literals and DOM assignments use `t()` directly:

```javascript
// Before
el.textContent = `Showing ${from}–${to} of ${total}`;

// After
el.textContent = t('vault.showing', { from, to, total });
```

```javascript
// Before
card.innerHTML = `<h3>Vault Status</h3>`;

// After
card.innerHTML = `<h3>${t('vault.heading')}</h3>`;
```

## Settings Schema

One new entry in `core/settings.py`. Use `'string'` (not `'str'`) to match the existing schema convention:

```python
'ui:language': {
    'type': 'string',
    'default': '',
    'label': 'Interface Language',
    'group': 'ui',
    'description': 'Override the interface language. Empty = use browser default.',
},
```

Empty string = browser default. `lcI18nLoad()` treats `''` and missing as `navigator.language`.

---

## Language Detection Order

```
settings.db  ui:language  (non-empty, found in manifest)
    ↓ fallback
navigator.language  (strip region tag: "fr-FR" → "fr"; must exist in manifest)
    ↓ fallback
"en"
```

The language must exist in `manifest.json`; an unrecognised code falls through to `'en'`.

---

## What Is NOT Translated

- File paths, vault names, extracted document text — user data
- API error messages from the backend — backend concern
- Sensor readings (numbers + units) — locale-aware formatting deferred
- Database status enums used as filter keys — internal values
- Timestamps, file sizes — locale-aware formatting deferred

## Out of Scope

- Right-to-left (RTL) layout support
- Plural forms (e.g. "1 file" vs "2 files") — use neutral phrasing in source strings
- Locale-aware number/date formatting
- Backend API message translation
- Language auto-detection beyond `navigator.language`
